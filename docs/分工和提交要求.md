# 期末大作业分工和提交要求

## 一、总体方案

开发一个采用 **Spring Boot 后端＋前端的自动化测试平台**，后端集成 **Apifox CLI** 执行测试，前端提供测试配置、任务执行、状态查询、报告查看和结果对比功能。
开发要求使用前后端分离开发。按照Restful API设计风格撰写前后端接口契约文档和开发，使用 Spring Boot 构建后端，前端使用 Vue 构建。

必须包含的主要功能如下：
| 序号 | 核心功能 | 你们的平台应做到什么 | 对应要求 |
|---|---|---|---|
| **1** | **多网站与环境管理** | 登记至少两个同类网站，保存地址、环境、可比业务页面及测试范围，执行时可切换。 | 支撑同工具测不同网站 |
| **2** | **HTTP请求配置与调试** | 配置URL、方法、参数、Header、Cookie和请求体，发送后查看响应头、正文、状态码及耗时。 | 为两类对比准备正确请求 |
| **3** | **测试用例、场景与断言管理** | 登记和复用请求、场景、工具脚本及预期结果；检查状态码、正文内容、字段或响应时间。 | 保证测的是正确业务，避免只看200 |
| **4** | **多工具统一执行入口** | 在平台选择Apifox CLI或JMeter，调用对应场景或计划，保存工具版本与执行配置。 | 支撑不同工具测同一网站 |
| **5** | **测试参数配置与多组实验** | 分别配置各工具支持的循环、间隔、线程、升压、运行时长等参数，保存多组方案并重复执行。 | 直接满足“调整不同参数” |
| **6** | **任务状态、日志与失败定位** | 查看排队、运行、完成、执行故障等状态；查看日志，区分目标请求失败、断言失败和工具故障。 | 让平台具备实际执行与排查能力 |
| **7** | **统一结果指标与可视化** | 展示样本数、平均响应时间、分位响应时间、吞吐量、错误率和断言通过率；明确单位与统计口径。 | 为两类对比提供可信数据 |
| **8** | **同工具、不同网站对比** | 固定工具和可比业务，在相同参数档位下比较多个网站，通过表格和曲线展示差异。 | 
| **9** | **同网站、不同工具对比** | 固定网站和业务场景，比较可比指标，并记录配置步骤、准备耗时、断言能力、报告质量和集成便利性。 |  
| **10** | **历史报告、复测与证据归档** | 保留每次配置、原始报告、日志和截图；能够复测、查看前后差异，并导出测试报告（必须包含.html和.md和.json格式，要求.json格式可下次导入还原上次被测情景） | 保证结论可追溯、成果可展示 |

示例被测网站为 **徐州工程学院官网：https://www.xzit.edu.cn/**。平台是本项目的成果，学校官网是实验对象，两者在架构、部署和报告中分别介绍。

建议报告题目：**基于 Spring Boot 与 Apifox CLI 的自动化测试平台设计与网站测试分析**。

项目地址：https://github.com/Invert-viewer/TestPilot。要求每次完成一个版本后及时推送GitHub上，并且写好规范的commit,要求commit尽量使用中文方便理解。

### 测试范围与工具安排

- **Apifox CLI 为核心工具**：围绕官网公开页面及实际确认存在的公开 HTTP 接口，进行请求执行、响应断言、参数化、循环执行和报告生成。返回 HTML 的页面按页面请求验证，不描述为 JSON 业务接口。
- **官网测试范围以实际勘查为准**：首页、公开栏目页、文章详情页为候选；搜索功能及其请求确认存在后再纳入。不预设官网存在登录、注册或增删改接口。
- **页面请求验证与浏览器 UI 检查分别记录**：Apifox CLI 验证 HTTP 响应；页面布局、脚本渲染和点击跳转另用人工检查或补充浏览器工具验证，不将 CLI 结果直接作为 UI 自动化证据。
- **保留老师的两项对比要求**：同一工具测试两个同类网站并调整参数；不同工具测试同一网站并比较功能、便利性和结果。第二个同类高校官网由 1 号组织选定并登记实际地址，仅测试学校官网尚不能完成第一项要求。
- **补充对比工具暂定 JMeter**：与 Apifox CLI 比较同一组 HTTP 请求的配置、断言、执行与报告。CLI 串行循环和响应时间统计不等同于并发压测；如开展并发性能实验，由 JMeter 承担，并具备被测方许可及明确负载范围。官网基础验证使用低频只读请求。

## 二、六人分工

每个人负责实际实现或测试、对应报告内容和答辩演示，不设置只负责排版或 PPT 的岗位。

| 人员 | 具体负责什么 | 报告负责部分 | 答辩可以讲、可以演示的内容 |
|---|---|---|---|
| **1号：Spring Boot 后端与集成** | 总体架构和数据库；项目与任务管理；调用 Apifox CLI；记录任务状态、退出码、日志和报告；结果保存与整体联调 | 第2章总体架构与后端；第7章总结；全文整合 | 从任务提交到 CLI 执行、报告回传的流程；如何区分执行失败和断言失败；现场发起一个小规模任务 |
| **2号：平台前端与结果展示** | 网站与环境配置、用例或场景选择、参数表单、任务列表、状态查询、结果详情、历史记录和对比图；对接后端 | 第2章前端实现与结果展示 | 演示选择官网、发起任务、查看报告与比较结果；解释接口对接、状态更新和指标展示 |
| **3号：官网勘查与 Apifox 测试资产建设** | 梳理实际可访问的公开页面和请求；制作清单；建立 Apifox 项目、环境、变量与基础用例；交付场景 ID 或可运行导出文件 | 第3章被测网站与测试方案 | 用例怎样从官网需求产生；公开页面与业务接口的区别；演示环境切换和基础场景，说明勘查中遇到的问题 |
| **4号：参数实验与多工具对比** | 与3号统一业务请求；设计循环次数、请求间隔等参数实验；选定第二网站后执行跨网站实验；编写 JMeter 对照脚本；分析工具便利性和实验结果 | 第4章参数实验与网站对比；第6章多工具对比 | 展示参数表、原始数据和图表；解释对比条件；区分串行响应统计与并发压测；说明工具适用场景 |
| **5号：HTTP 请求断言与回归测试** | 基于3号基础请求补充正常、异常、边界用例；验证状态码、Content-Type、正文关键内容及实际存在的结构化字段；记录失败、复测与回归结果 | 第5章 HTTP 请求与断言测试部分 | 展示正常与异常输入断言；解释请求成功为何不等于内容正确；演示失败定位和复测。异常测试限于已确认允许的低频只读请求 |
| **6号：页面检查与平台验收测试** | 检查官网代表性页面的导航、链接和显示，注明人工或浏览器工具；测试平台的参数校验、任务状态、失败提示、报告查看和历史记录；维护验收清单 | 第5章页面检查与平台验收部分 | 展示页面检查证据、平台异常处理、一个验收问题及复测；解释 HTTP 断言不能覆盖的浏览器行为 |

### 交接要求

1. **1号与2号**先确定后端接口和结果字段：任务 ID、网站、工具、执行参数、状态、时间、用例结果、日志和报告位置。
2. **3号向4号和5号**交付统一请求清单、环境变量、基础测试资产与运行说明；3号负责测试资产组织，5号负责断言深度和回归验证。
3. **4号负责实验方案与对比口径**，3号协助核实两个网站的业务可比性。统一请求语义、数据、请求节奏、环境、指标单位与重复次数，分别运行不同工具。
4. **1号负责平台调度，3—5号负责各自测试资产可运行**。先独立跑通小场景，再接入平台；6号从首次联调开始验收。
5. 各人提交本人章节的文字、代码或脚本、数据和配图，1 号统一结构与格式。官网无法访问等情况按实际现象记录，不直接判定为网站缺陷。

## 四、每个人的提交要求

| 必交内容 | 具体要求 |
|---|---|
| **实现成果** | 本人负责的代码、测试脚本、Apifox 测试资产或可复现的检查与验收用例；注明文件位置和运行方式 |
| **设计说明** | 写明负责范围、设计依据、实现或测试方法，以及与其他成员的交接内容 |
| **用例与预期结果** | 测试人员提交编号、目标、步骤、输入、预期结果和断言；开发人员提交模块验收步骤 |
| **结果证据** | 实际执行日志、原始数据、HTML/JSON 报告或检查截图；标明日期、环境、参数与对应任务或用例，不编造数据 |
| **问题与解决过程** | 至少一个真实问题及定位、处理和验证过程；无网站缺陷时可讲集成或测试执行问题，不强行编造缺陷 |
| **报告章节** | 本人负责的文字、表格、图片与参考来源；结论对应实际证据 |
| **答辩材料** | 本人负责部分的 PPT 内容和一个可复现演示片段，讲清做了什么、怎样做、结果如何、解决了什么问题 |

Apifox 访问令牌不放入前端、仓库、截图或普通日志。提交测试资产时保留变量名，移除令牌等敏感值。

## 五、阶段验收

1. **方案确认**：确定官网测试范围、第二个同类网站、工具组合、前后端接口与结果字段。
2. **最小流程跑通**：前端创建官网测试任务，Spring Boot 调用 Apifox CLI 执行小场景，生成报告并展示实际结果。
3. **个人模块完成**：交付可运行代码或测试资产及章节初稿，完成请求断言、页面和平台功能检查。
4. **正式对比实验**：按统一方案执行参数、跨网站与跨工具实验，保留原始记录并说明实验限制。
5. **整体答辩验收**：六个人均有独立成果、证据和演示；准备已生成报告及演示录屏，便于现场网络不稳定时说明结果。
