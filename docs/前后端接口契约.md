# TestPilot 前后端接口契约

本文按《分工和提交要求》和《前后端接口契约检查报告》补写，供 Vue3 前端、Spring Boot 后端和验收人员使用。以下路径是拟实现的业务接口。当前正式集成范围、写入事务与调试限制见第 10 节；历史规划中仍有未实现的接口。第 8 节汇总已确认的四项约定。

## 1. 请求与响应

接口前缀为 `/api/v1`。下文路径省略此前缀。现有 Axios 客户端的 `baseURL` 为 `/api`，接入时调用 `/v1/...` 即可。资源 ID 是字符串，时间使用带时区的 ISO 8601 字符串，耗时用毫秒。字段名采用 camelCase。

| 情形 | HTTP 与响应体 |
|---|---|
| 读取、更新、同步调试 | 200，JSON 外层为 `{code:"OK",message:"",data,traceId}` |
| 新建资源、提交异步任务 | 201 返回新资源。新任务返回 202 和任务摘要，供前端轮询。 |
| 平台错误 | 400 `VALIDATION_ERROR`、404 `NOT_FOUND`、409 表示资源状态或版本冲突、500 `INTERNAL_ERROR`。当前部署不启用目标白名单：被测地址只要求是 HTTP(S)，非法地址返回 400 `VALIDATION_ERROR`；`TARGET_NOT_ALLOWED` 仅保留给重定向到非法或不支持地址的场景（实现中为 `TARGET_REDIRECT_NOT_ALLOWED`）。错误码以具体接口为准。 |
| 文件 | 预览与下载成功时返回对应媒体类型，错误仍返回 JSON。前端先判断 HTTP 状态与 Content-Type。 |

字段错误示例。文中所有 ID 和数值仅用于核对格式。

```json
{"code":"VALIDATION_ERROR","message":"Cookie 请填写到 cookies","data":{"errors":[{"field":"headers[0].key","message":"该请求头由平台生成"}]},"traceId":"example-trace"}
```

**集合规则（C-05）。** 网站、请求、工具资产、参数方案、调试历史、任务、用例结果、对比和验收清单用 `{items,page,pageSize,total}`，从第 1 页开始，默认 20 条，最多 100 条。无记录返回 `items:[]`、`total:0`。环境和工具体验记录直接返回数组。任务日志单独使用游标。空列表展示空态，缺失指标展示“—”，单位由页面标注。

## 2. 网站、环境与资产

| 方法与路径 | 请求或筛选 | 成功返回 |
|---|---|---|
| `GET /sites`、`POST /sites` | 查询支持 `keyword`。新建提交 `name,baseUrl,scope,pages`，其中 `scope` 是测试范围说明，`pages` 每项为 `{scenarioKey,path}` | 分页或新建的网站 |
| `GET /sites/{siteId}`、`PUT /sites/{siteId}` | 更新提交同一组字段 | 含 `id` 的网站 |
| `GET /sites/{siteId}/environments`、`POST /sites/{siteId}/environments`、`PUT /sites/{siteId}/environments/{envId}` | 写入 `name,baseUrl,variables`。变量为名称到字符串值的对象 | 数组或含 `id,siteId` 的环境 |
| `GET /requests`、`POST /requests`、`GET /requests/{id}`、`PUT /requests/{id}` | 查询支持 `siteId,keyword`。写入第 3 节请求定义 | 分页或含 `id,version,definition` 的请求资产 |
| `POST /files`、`GET /files/{fileId}` | 上传使用 multipart 字段 `file,purpose`。用途 `TOOL_ASSET` 接受可运行的 Apifox JSON 或 JMeter JMX，`EVIDENCE` 接受截图或 PDF | 上传返回 `{id,name,contentType,sizeBytes}`，下载返回对应文件 |
| `GET /tool-assets`、`POST /tool-assets`、`GET /tool-assets/{id}`、`PUT /tool-assets/{id}` | 查询支持 `tool,scenarioKey`。写入 `name,tool,kind,source,scenarioKey,requestRefs` | 分页或含 `id,version` 的资产详情 |
| `DELETE /tool-assets/{id}` | 资产 ID，无需正文 | 200 `{id,deleted:true}`。仍有任务引用时 409 `TOOL_ASSET_IN_USE`，需先删除引用任务。删除会写入 `tool_asset_tombstone`，服务重启不会按配置重新登记该种子资产 |

`scenarioKey` 标识同一业务，例如经勘查确认的两站首页可共用该值。`path` 为站内路径。网站和环境的 `baseUrl` 必须是 HTTP(S) 地址，允许路径前缀，禁止凭据、查询和片段。创建和更新时即校验网站归属与地址格式（C-02，第 8 节）。当前部署不启用目标白名单：被测地址只要求是 HTTP(S)，非法地址返回 400 `VALIDATION_ERROR`。调试请求发送前和每次跟随重定向前，后端都重新校验解析后的地址，只接受 HTTP(S) 目标。官网基础场景只登记低频只读请求。

`tool` 为 `APIFOX_CLI` 或 `JMETER`。`APIFOX_SCENARIO` 的 `source` 含真实 `projectId,scenarioId` 和可选的 Apifox `environmentId`。`APIFOX_FILE` 与 `JMETER_FILE` 使用 `{fileId}`，工具与资产类型必须对应。平台环境 ID 与 Apifox 环境 ID 分开保存。`requestRefs` 每项为 `{id,version}`，用于记录场景对应的请求与预期结果。3 号交付的资产需先独立跑通，后端只接收已登记的资产引用和结构化参数。已执行任务始终引用当时版本。

## 3. HTTP 请求调试与断言

请求定义同时用于调试、保存用例和登记预期结果。下面是一条针对示例网站首页的请求格式。

```json
{
  "name":"首页返回 HTML","siteId":"site-example","environmentId":"env-example",
  "method":"GET","url":"{{baseUrl}}/","charset":"UTF-8",
  "query":[],"headers":[],"cookies":[],"body":{"mode":"NONE"},
  "timeoutMs":5000,"followRedirects":true,
  "assertions":[{"id":"a1","type":"HEADER","target":"Content-Type","operator":"CONTAINS","expected":"text/html","enabled":true}]
}
```

- 方法接受 `GET/HEAD/POST/PUT/PATCH/DELETE/OPTIONS`，执行权限取决于目标登记范围。URL 可用绝对地址或环境变量模板。查询、请求头、Cookie 和表单均使用 `{key,value,enabled}` 数组，按顺序处理启用项。查询可重复键，批量编辑由前端转换成同一数组。
- 字符集支持 `UTF-8/GB18030`。正文模式为 `NONE`、`FORM_URLENCODED`（`fields` 数组）、`JSON`（`text` 为合法 JSON 文本）或 `RAW`（`text`）。GET、HEAD 使用 NONE。超时填写正整数毫秒。启用重定向时最多跟随五次。
- **请求头（C-08）。** Cookie 只从 `cookies` 生成。拒绝手填 Cookie、Host、Content-Length、Transfer-Encoding 和 Connection，头名大小写等价。JSON 和表单的 Content-Type 根据正文模式生成，显式填写时须与模式、字符集一致且只发送一份。RAW 可指定 Content-Type。重复请求头、冲突或保留头均返回字段级 400。
- **断言（C-03）。** 配置 `Assertion` 含 `id,type,target,operator,expected,enabled`。类型 `STATUS_CODE` 支持 `EQ`，`HEADER/BODY/JSON_FIELD` 支持 `EQ/CONTAINS`，`RESPONSE_TIME_MS` 支持 `LTE`。HEADER 的 target 是头名，JSON_FIELD 为 JSON Pointer，其余为 null。expected 使用字符串，状态码和耗时按数值比较。响应缺少预期字段或无法解析 JSON 时返回 FAILED 和原因。禁用或因传输失败无法执行时为 SKIPPED。
- **断言结果。** `AssertionResult` 保留 `id,type,target,operator,expected` 并返回 `actual,status,message`。status 为 `PASSED/FAILED/SKIPPED`，缺少实际值时 actual 为 null，无补充说明时 message 为 null。调试和任务用例详情均返回 `AssertionResult[]`。

| 方法与路径 | 输入 | 返回 |
|---|---|---|
| `POST /http-debug/executions` | 请求定义 | 同步执行记录 |
| `GET /http-debug/executions` | `siteId,keyword,outcome,page,pageSize` 均可省略（C-09） | 分页摘要，含 ID、请求名、时间、状态码、耗时与结论 |
| `GET /http-debug/executions/{id}`、`POST /http-debug/executions/{id}/rerun` | 读取详情或重放已保存的请求，重放时重新校验目标 | 原记录或新执行记录 |

执行记录包含 `id,createdAt,definition,transportStatus,outcome,requestHeaders,response,durationMs,assertions,error`。response 有 `statusCode,headers,bodyText,bodyEncoding,sizeBytes,truncated`。头使用可重复的 `{key,value}` 数组。文本返回原始正文，格式化由前端完成。二进制预览时 bodyEncoding 为 `base64`，文本为 `text`。无响应时 response 为 null。头、正文和历史记录中涉及的敏感值在展示及归档前脱敏。

| 情形（C-01） | HTTP | 记录与前端显示 |
|---|---|---|
| 初始目标不是 HTTP(S) 地址 | 400 | `VALIDATION_ERROR`，无执行 ID |
| 已完成请求，下一跳地址非法或超过上限 | 200 | 保存记录，传输状态 FAILED，error.code 分别为 `TARGET_REDIRECT_NOT_ALLOWED`、`TARGET_REDIRECT_LIMIT_EXCEEDED` |
| DNS、TLS、连接失败或超时 | 200 | 保存 FAILED，error 含 `code,message`，outcome 为 NOT_EVALUATED |
| 目标返回 HTTP 响应（包括 404、500） | 200 | 保存 COMPLETED，展示目标状态码与断言明细，error 为 null |

传输失败的调试记录统一为 `NOT_EVALUATED`。收到响应后，任一断言失败则为 `FAILED`，有通过且其余均通过或跳过则为 `PASSED`，全部跳过或未配置则为 `NOT_EVALUATED`。这三个值也是调试历史 outcome 的合法筛选值。

例如目标实际返回 404 而用例预期 200，调试接口仍返回 200。执行记录中与结果有关的字段如下，前端可直接显示期望值和实际值。

```json
{
  "transportStatus":"COMPLETED","outcome":"FAILED","error":null,
  "response":{"statusCode":404,"headers":[],"bodyText":"","bodyEncoding":"text","sizeBytes":0,"truncated":false},
  "assertions":[{"id":"a2","type":"STATUS_CODE","target":null,"operator":"EQ","expected":"200","actual":"404","status":"FAILED","message":"实际状态码为 404"}]
}
```

## 4. 参数方案、任务及结果

| 方法与路径 | 输入 | 返回 |
|---|---|---|
| `GET /parameter-plans`、`POST /parameter-plans`、`GET /parameter-plans/{id}`、`PUT /parameter-plans/{id}` | 列表按 tool 筛选。写入 `{name,tool,parameters}` | 分页或含 id、version 的方案 |
| `POST /tasks` | `Idempotency-Key` 和下例请求体。parameters 可直接指定，也可用 `parameterPlanId` 代替 | 202 任务摘要，同键重试见第 8 节 |
| `GET /tasks`、`GET /tasks/{id}` | 列表可按 `siteId,tool,status,outcome` 筛选 | 分页摘要或含执行快照、工具版本、退出码、故障信息的详情 |
| `POST /tasks/{id}/cancel`、`POST /tasks/{id}/rerun` | 取消无需正文。复测使用新幂等键和原快照 | 取消返回当前摘要。复测返回新任务，`sourceTaskId` 指向原任务 |
| `DELETE /tasks/{id}` | 任务 ID，仅终态（FINISHED、CANCELLED、ERROR）可删 | 200 `{id,deleted:true}`，同时删除该任务的日志、用例结果与报告目录，并清理共享配置中对它的引用（实验方案 taskIds 移除、检查记录 taskId 置空、工具体验记录删除）。非终态返回 409 `TASK_NOT_DELETABLE`，不存在返回 404 |
| `GET /tasks/{id}/logs` | 可传 `cursor,limit`，首次省略 cursor | `{items,nextCursor,hasMore,complete}`，每项含 `time,stream,text`，stream 为 STDOUT、STDERR 或 PLATFORM。无新日志返回空数组并保留读取位置，首次无日志时游标为 null。complete 表示日志已封存，读完末页才停止拉取 |
| `GET /tasks/{id}/results`、`GET /tasks/{id}/results/{caseId}` | 列表分页，可按 `status` 筛选 | 用例行含 `caseId,name,status,durationMs,statusCode,failureKind`，详情另含 assertions 和错误说明 |
| `GET /tasks/{id}/report` | 任务 ID | `{taskId,summary,metrics,files}`，files 含原始产物的文件 ID、名称、类型与大小，统计规则见第 5 节 |

Apifox CLI 参数为 `iterations,delayRequestMs,timeoutRequestMs`。JMeter 参数为 `threads,rampUpSeconds,loops`，可选 `durationSeconds,delayRequestMs`。次数、线程及启用的时长为正整数，间隔与升压可为零。JMeter 计划按同名参数取值，指定时长时，达到时长或完成循环即结束。后端校验参数所属工具、资产版本、环境归属、请求范围与该目标获准的负载条件。命令行参数由后端生成。

```json
{
  "name":"官网首页基础验证","siteId":"site-example","environmentId":"env-example",
  "tool":"APIFOX_CLI","assetId":"asset-example","assetVersion":1,
  "parameters":{"iterations":1,"delayRequestMs":1000,"timeoutRequestMs":5000}
}
```

```json
{
  "code":"OK","message":"","traceId":"example-trace",
  "data":{
    "id":"task-example","name":"官网首页基础验证","siteId":"site-example","environmentId":"env-example",
    "tool":"APIFOX_CLI","status":"QUEUED","terminal":false,"outcome":"NOT_EVALUATED",
    "createdAt":"2026-11-11T12:00:00+08:00","startedAt":null,"finishedAt":null,"sourceTaskId":null,
    "summary":{"totalCases":null,"passedCases":null,"failedCases":null,"skippedCases":null,"notEvaluatedCases":null}
  }
}
```

提交时保存目标、环境、请求与断言、工具资产版本及有效参数快照。导入草稿还可传 `sourceTaskId` 以关联来源，首次运行省略。工具启动后记录实际 `toolVersion`，退出后记录 `exitCode`，未知时为 null。只有工具或平台故障才将任务标为 ERROR。执行器结合退出码、原始报告和日志判别断言失败，避免把正常产出失败用例报告的任务一律判成工具故障。

| 任务状态（C-06） | terminal | 页面行为 |
|---|---|---|
| QUEUED、RUNNING | false | 轮询状态，可申请取消 |
| CANCELLING | false | 继续轮询，等待执行器确认 |
| FINISHED | true | 停止状态轮询，读取用例结论和报告 |
| CANCELLED、ERROR | true | 停止状态轮询，显示可用日志、故障说明或已归档证据 |

排队任务可直接取消，运行中取消先进入 CANCELLING。任务终态保持不变，重复取消已取消任务返回 200，取消已完成或故障任务返回 409。复测从终态创建独立任务。用例 status 为 `PASSED/FAILED/SKIPPED/NOT_EVALUATED`，分别指通过、失败、明确跳过、已记录但无法评价。failureKind 可为 `REQUEST`（目标或传输失败）、`ASSERTION` 或 null。工具故障记录在任务详情的 `error:{code,message}`。FINISHED 的 outcome 在存在失败用例时为 FAILED，有通过且无失败时为 PASSED，其余为 NOT_EVALUATED。其他任务状态的 outcome 为 NOT_EVALUATED。

**计数（C-04）。** 各状态使用同一份 TaskSummary。未取得完整用例统计时五项均为 null，原始日志和已取得的明细仍可读。解析成功且没有用例时五项均为 0。有完整统计时 `totalCases = passedCases + failedCases + skippedCases + notEvaluatedCases`。任务列表、详情和报告读取同一份摘要。

## 5. 指标与两类实验

每个 HTTP 样本对应一次实际请求尝试。用例和断言各有独立计数，一个用例可包含多个请求或断言。两种工具按相同的请求范围汇总，保存样本数、原始数据来源与统计区间。缺少原始分类、计数或时间字段时，受影响的指标返回 null。

| metrics 字段 | 单位与计算 |
|---|---|
| `sampleCount,avgResponseMs,p95ResponseMs` | 样本数为实际尝试数。对有可核实耗时的样本（含失败请求）取算术平均，P95 取升序第 ⌈0.95 × n⌉ 项，从 1 起算。返回耗时样本数 `timedSampleCount`。 |
| `throughputRps,errorRate` | 吞吐量为样本数除以从首个请求开始到最后一个请求结束的秒数。错误率为失败请求数占全部请求数的百分比，失败归类见第 8 节。 |
| `passRate,evaluatedPassRate` | 整体用例通过率为 passedCases / totalCases × 100，已评估通过率为 passedCases / (passedCases + failedCases) × 100。 |
| `assertionPassRate` | 通过断言数 /（通过断言数 + 失败断言数）× 100。报告保留 `passedAssertions,failedAssertions,skippedAssertions`。没有断言级证据时该指标为 null。 |

验算示例：5 次请求中，1 次返回 503，1 次连接超时，另有 1 次返回 200 但正文断言失败，其余 2 次正常。报告的 `errorSampleCount` 为 2，`errorRate` 为 40。正文不符的那一次在断言明细中显示 FAILED。

| 方法与路径 | 输入 | 返回 |
|---|---|---|
| `POST /comparisons` | `{name,mode,scenarioKey,groups}`，每组为 `{label,taskIds}`。label 对应一个参数档位，taskIds 包含该档位各目标或工具的重复任务 | 201 对比详情 |
| `GET /comparisons`、`GET /comparisons/{id}` | 列表支持 mode | 分页或详情。详情含 `id,name,mode,scenarioKey,groups,rows,differences` |
| `GET /comparisons/{id}/experiences`、`POST /comparisons/{id}/experiences` | 写入 `tool,taskId,setupSteps,prepMs,runMs,assertionNotes,reportNotes,integrationNotes,evidenceFileIds` | 数组或新记录（含 id） |

- `CROSS_SITE` 固定工具和可比业务，每档都含至少两个不同网站及相同工具参数。两个网站的真实页面可以有不同路径。使用同一批网站、相同请求语义和重复次数，表格和曲线按档位展示。
- `CROSS_TOOL` 固定网站、环境和业务，每档都含 Apifox CLI 与 JMeter。统一输入、断言、请求节奏、运行条件和重复次数。工具体验记录保留实际步骤与耗时，用于说明哪种工具在该场景更方便。
- 只有带真实完整报告的 FINISHED 任务可加入。模式、网站数、工具数或任务归属错误返回字段级 400。每条 row 含 `label,taskId,siteId,tool,parameters,summary,metrics`，可追溯到原始报告。已知条件差异记为 `{field,taskIds,description}`，串行与并发结果分开展示，受影响的指标不计算差值。图表的空值保留断点。

## 6. 报告归档、导出与场景还原

| 方法与路径 | 输入 | 成功返回 |
|---|---|---|
| `GET /tasks/{id}/report/view` | 任务 ID | 200 原始 `text/html; charset=utf-8`，预览与错误规则见第 8 节（C-10） |
| `GET /tasks/{id}/report/export` | 必填 `format=html/md/json` | 200 下载文件，Content-Disposition 给出含任务 ID 的文件名。媒体类型依次为 text/html、text/markdown、application/json。JSON 文件直接保存下述归档对象。 |
| `POST /reports/import` | 将导出的归档对象作为 application/json 正文提交 | 200 `{draft,readyToRun,issues}`。导入只还原配置，用户核对后通过 POST /tasks 创建新任务。 |

导出 HTML、Markdown 包含目标、实际参数、结果统计、断言和证据索引，原始工具产物按 report.files 下载。JSON 兼作场景归档，至少包含以下字段。

| 字段 | 内容 |
|---|---|
| `schemaVersion,sourceTaskId,exportedAt` | 本格式 schemaVersion 为 1。源任务 ID 仅用于追溯。 |
| `snapshot.site,snapshot.environment` | 当时的网站范围、环境地址、非敏感变量、所需敏感变量名称。 |
| `snapshot.tool,snapshot.toolVersion,snapshot.asset,snapshot.requests,snapshot.parameters` | 工具、执行时版本、资产类型与来源、版本和场景标识、完整请求与断言、有效参数。文件型资产归档包含可恢复的已脱敏文件内容及摘要。云端场景保存项目与场景引用，并记录可取得的版本或导出副本。 |
| `summary,metrics,files` | 历史结果与原始证据索引。导入后这些字段仍属原任务。 |

文件型资产在 `snapshot.asset.archiveFile` 保存 `{name,contentType,dataBase64,sha256}`，摘要取自脱敏后文件的原始字节。snapshot.requests 每项为 `{id,version,definition}`，definition 使用第 3 节格式。归档保留场景使用的非敏感变量与敏感变量占位名称。认证头、Cookie 值和令牌在日志、归档和截图中脱敏，复测时从执行环境补入。

导入返回 `draft:{snapshot,task}`。snapshot 用于逐项核对，task 是第 4 节可提交的请求体，带 sourceTaskId。全部引用与版本匹配时 readyToRun 为 true、issues 为空数组。缺变量、缺资产或云端场景版本无法核实时，保留 snapshot，task 为 null，readyToRun 为 false。issues 每项含 `field,code,message`。前端按第 2 节登记或重新绑定资源，文件副本按摘要匹配，补齐后再导入。不识别的 schemaVersion 或损坏的文件返回 400。执行前重新校验目标范围。

## 7. 页面检查、平台验收与复测证据

| 方法与路径 | 输入 | 返回 |
|---|---|---|
| `GET /checks`、`POST /checks`、`GET /checks/{id}`、`PUT /checks/{id}` | 列表按 kind、status 筛选。写入 `kind,title,steps,expected,actual,status,method,siteId,taskId,evidenceFileIds,retestOfId` | 分页或含 id、updatedAt 的检查记录 |

kind 为 `WEBSITE_PAGE/PLATFORM`，method 为 `MANUAL/BROWSER/HTTP`，status 为 `PENDING/PASSED/FAILED`。steps 为字符串数组。与网站、任务或上次检查无关联时相应 ID 为 null，待执行时 actual 为 null。截图或 PDF 通过第 2 节的文件 ID 关联。复测新建记录并填写 retestOfId，保留原始现象与证据。页面显示和点击行为填写实际人工或浏览器方法。

联调验收可按以下顺序进行。

1. 新建网站与环境，拒绝非法地址。分别调试一次非 HTTP(S) 地址、重定向到非法地址和目标返回 404 的请求，核对平台 HTTP 状态、执行 ID 与历史筛选。
2. 提交一次小场景，再用同键并发重试。只产生一个任务和一次执行。核对日志游标、任务终态和报告摘要。用一次断言失败及一次工具故障检查页面能区分两者。
3. 从同一任务导出三个格式。重新导入 JSON，以还原的配置复测，核对资产、断言、参数、源任务关联和新任务 ID。
4. 分别用两站同工具、同站两工具的实际任务生成对比。抽查一组原始样本重算错误率、P95 与两种用例通过率，验证缺失数据和零分母的显示。

## 8. 已确认的四项约定

| 审查项 | 前后端统一行为 |
|---|---|
| C-02 环境归属 | 环境须与所属网站同源（协议、主机和有效端口相同）。保留环境 baseUrl 的路径前缀。拼接 `{{baseUrl}}/news` 时只合并连接处的斜杠，如 `https://example.edu.cn/public/` 与 `/news` 得到 `https://example.edu.cn/public/news`。当前部署不启用目标白名单，非 HTTP(S) 地址或格式错误的地址返回 400。 |
| C-07 任务幂等 | 创建与复测必传 `Idempotency-Key`。同一提交意图的重试沿用一个键，每次有意新建任务使用新键。后端原子登记键与提交内容，首次返回 202。同键同内容返回 200 和原任务的当前摘要，同键异内容返回 409 `IDEMPOTENCY_CONFLICT`，缺键返回字段级 400。比较规范化请求内容，包含操作及复测源任务，忽略 JSON 对象键顺序。幂等键随任务保存。 |
| C-10 报告预览 | 前端在受限 iframe 中打开平台生成的自包含 HTML，样式内嵌，动态文本转义，预览不依赖工具的外部脚本或资源路径。任务存在而报告未就绪时，报告详情、预览、导出均返回 409 `REPORT_NOT_READY`。任务不存在时返回 404 `NOT_FOUND`。文件缺失时按文件 ID 返回 404。 |
| 错误率和通过率 | errorRate 将 HTTP 4xx/5xx 与 DNS、TLS、连接失败、请求超时等传输失败计为错误，每个请求样本最多计一次。纯断言失败只计入断言及用例结果。两工具均按原始请求证据分类。所有比率分母为零时返回 null，界面显示“—”。整体与已评估用例通过率分列显示。 |

## 9. 本地前端配置扩展

任务快照的 parameters 已扩展以下字段，字段与 CLI 选项以本机 run 帮助核对。后端接入时应补齐这些字段的校验及执行映射。

| 配置 | 前端字段及对应选项 |

| 目标与项目 | targetKind、targetId 对应场景、目录、套件、用例目标。collection 对应文件或 URL。projectId、branch、apifoxEnvironmentId 对应项目、分支和工具环境。 |

## 10. 平台实际集成（2026-11-13）

部署者电脑的 Spring Boot 同源提供 Vue 生产静态文件和 /api/v1。沿用 MySQL、JdbcTemplate、schema.sql、既有任务接口、分页、游标和 JSON 错误信封。任务执行资料继续通过 tool_asset 登记。共享资产草稿是工作区记录，保存草稿不会登记新的可执行工具。

- GET /workspace 返回按 sites、environments、requests、assets、parameterPlans、comparisons、comparisonExperiences、assertionCases、checks 分组的对象，每组为数组，每行有字符串 id 和正整数 revision。
- POST /workspace 接收变更数组，每项为 {collection,id,revision,value}。创建 revision=0，修改或删除提供上次读到的版本。value 为完整资源对象，删除时为 null。返回提交后的完整快照。版本冲突为 409 VERSION_CONFLICT；字段或引用错误为 400 VALIDATION_ERROR，data.errors 含字段位置。任何一项出错整批回滚。一次网站操作可以同时维护其环境和关联。
- 单资源客户端可 GET/POST /sites、/requests、/checks、/parameter-plans、/comparisons，以及 GET/PUT 对应 /{id}。支持第 1 节分页；更新可携带 revision 以拒绝过期写入。GET/POST /sites/{id}/environments、PUT /sites/{id}/environments/{env} 维护同源环境。界面的实验档位保留 groups，来源任务保留 taskIds，平台共享期间读取来源任务的真实详情计算对比数据。
- 直接 URL 的请求定义使用空字符串 siteId、environmentId；通过环境调试时，前端保留原定义，在发送前展开 URL 变量。POST /http-debug/executions 只接收被测请求定义，按启用顺序编码 query 和表单，由独立 HTTP 客户端发起，平台请求头不参与转发。返回 id、resolvedUrl、durationMs、transportStatus、outcome、assertions、response、error。目标 HTTP 错误仍保留响应；连接失败和超时保留传输错误，断言 SKIPPED。
- 调试目标不启用白名单，请求定义可直接填写任意 HTTP(S) URL；非 HTTP(S) 地址返回 400 VALIDATION_ERROR，不发起请求。跟随重定向时每跳重新校验，重定向到非法或不支持地址返回失败执行结果，error.code 为 TARGET_REDIRECT_NOT_ALLOWED；跨来源不复制凭据，最多 5 跳。超时 1–60000 ms，单次响应预览最多 256 KiB。Set-Cookie 响应头隐藏。真实及模拟调试结果保留在当前会话；GET 历史、服务端重放和完整响应内容持久化未接入。保存请求定义是独立操作。
- 持久化新增 workspace_resource(kind,id,revision,payload)、workspace_lock 和 tool_asset_tombstone；保留 tool_asset、task、task_log、task_result 及报告目录。新增建表可重复执行。使用者以显式操作导入旧版网站、环境和请求，保留原始 ID，已存在则跳过。
- 删除共享资源统一走 POST /workspace，value 为 null。后端在同一事务内级联清理悬空引用：删除网站会删除它的环境、绑定该网站的请求和引用这些请求的断言用例，把检查记录的 siteId 置空，并从实验方案的 siteIds 移除该网站；删除请求会删除引用它的断言用例；删除实验方案会删除它的 comparisonExperiences。清理后仍不满足引用校验时整批回滚并返回 400 VALIDATION_ERROR。删除页面、环境等资源前，界面需二次确认。
