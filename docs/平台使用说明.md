# TestPilot 平台使用说明

平台不做登录鉴权：部署者运行服务，其他人用浏览器访问同一平台，所有使用者权限相同。

## 使用者打开与使用

连接部署者所在的局域网，在浏览器打开部署者电脑的无线或以太网 IPv4 地址，例如本次的 http://192.168.5.197:8080/#/debug 。平台前端、API 共用 8080 端口。使用者只需浏览器。

- **发送真实请求**。直接填写完整 URL、方法、参数、请求头、Cookie、正文和断言，点击「发送真实请求」。响应来自部署者电脑访问的被测服务器。预填地址是部署者电脑上的测试博客。「运行本地调试」使用选定的模拟情形。调试历史只存在当前页面会话；点击「保存请求」后才成为平台共享的请求资产，其他人刷新即可载入。
- **运行 Apifox 场景**。点「新建任务」，选择后端登记场景，确认执行目标、环境和参数，再点「提交真实任务」。保存任务详情页链接。其他使用者打开同一链接即可看日志、断言和报告。
- **资源与记录**。网站、所属环境、请求资产、资产草稿、参数方案、实验、工具体验、断言回归和检查记录由同一数据库保存。删除网站时同步移除环境及实验、检查里的站点关联。若已有请求引用该站点，删除会整体回滚。先在「请求调试」载入这条已保存请求，改为直接 URL、解除环境绑定并保存，再删除。任务与报告使用其原始执行记录。遇到版本冲突，请刷新后核对其他人的改动再编辑。
- **旧版数据**。在旧版使用过的同一浏览器和地址（含端口），进入新版网站页，点「导入此浏览器旧版网站与请求」。旧版便携包与平台通常端口不同。可将仓库 frontend/portable/导出旧版配置.html 复制到自己旧便携包的 dist 目录，通过原来的端口打开 /导出旧版配置.html 下载 JSON，再在新平台使用「导入旧版导出文件」。同 ID 跳过，原 localStorage 保留。导入前可检查文件里的环境变量和请求凭据。

## 部署者准备和启动

1. 安装 JDK 21，设置 JAVA_HOME。使用已构建的项目需保留 target 中的 Spring Boot 可执行 JAR 和 frontend/dist。首次从源码构建另需 Node/npm、Maven Wrapper 依赖或本机缓存。
2. 启动 MySQL 8，准备 testpilot 数据库。用 local-application.example.yaml 配置被忽略的 local-application.yaml，填写有该库建表和读写权限的账号。已有库继续使用原配置。启动会幂等建表，无需导入旧报告或手工删表。
3. 调试目标不再需要目标白名单：请求调试里填完整的 HTTP(S) URL 即可，网页不需要预先登记网站。平台只接受 HTTP(S) 地址，其他协议或非法地址返回 400 `VALIDATION_ERROR`；被测地址重定向到非法或不支持的地址时返回失败执行结果，`error.code` 为 `TARGET_REDIRECT_NOT_ALLOWED`。请求由部署者电脑发起，127.0.0.1 等环回地址指部署者电脑。
4. 已登记场景使用部署者电脑上已登录的 Apifox CLI。其他电脑可用 APIFOX_CLI_PATH 设置实际 apifox.cmd 路径。参考场景需要匹配其路径与页面内容的博客。在本项目所在电脑，可另开窗口执行下列命令，保留窗口。

   ```powershell
   python -m http.server 4000 --bind 127.0.0.1 --directory "F:\SoftwareTest\期末大作业\静态博客网站测试\public"
   ```
5. 在项目根目录双击「启动平台.bat」。浏览器打开 http://127.0.0.1:8080/#/debug 。另开 PowerShell，在项目根运行下列健康检查。Spring Boot 直接提供 Vue 静态产物，正式模式无需 Vite、前端代理或原便携包。

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\检查平台.ps1
   ```
6. 用 ipconfig 查看实际联网网卡 IPv4，把对应地址发给其他人。选择可信专用网络，仅对局域网段开放入站 TCP 8080；不要做公网端口映射。MySQL、CLI 凭据和调试目标的本机文件仅由部署者使用。
7. 更新源码后，等任务结束，Ctrl+C 关闭原启动窗口；若服务在后台运行，可在部署者本机执行 `Invoke-RestMethod -Method Post http://127.0.0.1:8080/api/v1/admin/shutdown`。Windows 正在使用的 JAR 需要退出后才能重新打包。从项目根运行：

   ```powershell
   cd frontend
   npm ci
   npm run typecheck
   npm test
   npm run build
   cd ..
   .\mvnw.cmd package
   .\启动平台.bat
   ```

## 出错时按现象定位

| 现象 | 核对位置 |
|---|---|
| 8080 已占用或显示旧页面 | 查看原启动窗口、监听 PID、是否从正确项目目录启动；优雅关闭旧平台再启动 |
| 启动出现 Access denied、Unknown database、Communications link failure | MySQL 服务、库名、JDBC 地址和本机配置中的账号 |
| 启动出现 schema.sql 或 SQL initialization 错误 | 找到启动窗口中失败的 SQL 和数据库权限；保留现有表与数据 |
| 首页 404、API 正常 | 核对 frontend/dist/index.html 与启动目录，重新构建前端 |
| 首页正常、共享查询失败 | 检查 /api/v1/workspace 的 HTTP 状态、错误码和 traceId，确认启动的是新版后端 |
| 本机可用、其他人打不开 | 核对同一局域网、真实网卡地址、8080 入站规则和校园网客户端隔离；其他人可执行 Test-NetConnection 部署者IP -Port 8080 |
| 400 VALIDATION_ERROR | 检查被测 URL 是否为完整的 HTTP(S) 地址，是否误填了其他协议、凭据或片段 |
| TARGET_REDIRECT_NOT_ALLOWED | 目标站点发生重定向，且 Location 不是可用的 HTTP(S) 地址；核对被测站点的跳转配置 |
| REQUEST_TIMEOUT / CONNECTION_ERROR | 从部署者电脑访问相同被测地址，核对服务、证书、网络或超时。目标返回 404/500 时页面显示其真实状态码 |
| CLI 启动或登录故障 | 核对任务日志、部署者账号的 apifox --version、已登录状态、场景权限和资产配置 |
| FINISHED 且断言失败 | 查看失败用例与预期/实际值，核对实际被测博客版本，使用任务报告确认结果 |

## 第二台电脑复核

使用者用自己的浏览器访问部署者发来的平台地址，新增一条带自己姓名的网站配置。部署者刷新查看并编辑，使用者刷新核对。再换一台电脑的浏览器打开本次验收记录中的任务链接，查看同一个 taskId 的报告。
