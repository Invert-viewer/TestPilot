# 整体流程使用说明

## 1. 先确定本次使用哪种数据

| 页面 | 当前数据来源 | 本包能做什么 |
|---|---|---|
| 概览 | Spring Boot 任务 | 连接后端后查看真实统计、图表和任务明细 |
| 网站与环境 | 浏览器本地演示 | 新增、编辑网站与环境，填写变量，导出配置 |
| 测试资产 | 后端登记场景 + 本地资产草稿 | 上方真实场景可用于任务；下方草稿仅本地保存 |
| 请求调试 | 浏览器本地模拟 | 编辑请求、双模式录入、批量键值、按所选情形计算断言 |
| 任务与报告 | Spring Boot + 后端机器上的 Apifox CLI | 创建真实任务、看状态/日志/用例/断言、查看和下载脱敏报告 |
| 实验对比 | 本地方案 + 后端任务证据 | 配置两类实验，核对来源、缺项、档位与重复次数，记录工具体验 |
| 断言回归 | 浏览器本地演示 | 维护用例、预期、现象和回归说明；真实断言到任务详情查看 |
| 检查验收 | 浏览器本地记录 | 记录步骤、实际现象、证据与复测关联 |

网页会保留清楚的数据来源标记。本地模拟结果不能填写成真实官网测试结果。

## 2. 无后端时，先熟悉操作

1. 双击启动脚本进入「请求调试」，直接填写完整 HTTP(S) 地址即可运行本地模拟。
2. 需要复用配置时，从「网站与环境」点击「添加网站」。每张卡片可进入调试、编辑或删除网站及所属本地环境。
3. 到「测试资产」维护本地草稿。没有后端时，上方真实场景列表显示连接错误，这是实际状态。
4. 到「请求调试」，按需选用已保存的环境，填写方法与 URL，逐行添加 Query、Header、Cookie。
5. 点击「整段 JSON 录入」，修改一个参数值，再点击「逐字段填写」核对同步结果。未完成必填项也能切换。
6. JSON 语法或结构错误时仍能回到表单；未应用的 JSON 会保留，切回 JSON 可继续修改。点击「使用当前表单重新生成 JSON」会显式替换这份未应用草稿。
7. 在「本地响应情形」中选择 HTML、JSON、404 或超时，再点击「运行本地调试」，查看模拟响应和断言。这一步不会向填写的 URL 发出真实 HTTP 请求。
8. 到「断言回归」「检查验收」填写自己的用例、步骤和记录。尚未检查的项目保持待检查，不要直接标记通过。

表格在窄屏下可以横向滚动，纵向滚轮继续滚动页面；长弹窗在内容区滚动，顶部关闭和底部保存操作保留。

## 3. 跑一条真实任务

### 先准备后端与部署环境

1. 启动原项目的 Spring Boot 和数据库，确认 `GET /api/v1/tool-assets?tool=APIFOX_CLI` 可用。
2. 在**后端所在电脑**准备 Apifox CLI、有效登录和与登记场景匹配的被测站点。
3. 给其他人提供可访问的后端地址。其他人把它填入本包 `config.json`，重启前端。

当前已登记的参考资产为 `asset-apifox-8863397`，场景 `8863397`，项目 `8941754`，Apifox 环境 `49735657`，目标 `http://127.0.0.1:4000`。这里的 4000 指向**运行 CLI 的后端电脑**。本包不含被测静态博客站点；参考流程使用与该场景匹配的旧构建。不要把该场景描述成已经验证了学校官网。

### 在前端执行

1. 在任意页面点击「新建任务」。
2. 选择后端已登记场景，网站和环境随场景载入。
3. 核对面板中显示的**真实执行目标、环境和场景 ID**。草稿网站和高级 CLI 草稿不会覆盖这些登记信息。
4. 填写任务名称；初次联调使用循环 1 次、间隔 100 ms、请求超时 5000 ms。这里只发送后端支持的三个参数。
5. 点击一次「提交真实任务」，立即保存实际 taskId。重复点击会共享提交；若结果未知，按原内容重试会复用原幂等键。修改实际提交内容后视为新提交。
6. 查看「概览」「执行日志」。终态停止状态轮询，日志继续读取到封存。
7. 在「用例结果」筛选失败，点「查看」，逐项核对预期、实际值、失败原因及请求失败/断言失败的分类。
8. 打开「报告」，查看后端脱敏 HTML，下载 run.json / run.xml 等实际产物。刷新页面或用同一后端的 taskId 深链接重开，仍应定位同一任务。
9. 将 taskId、网站/环境/场景、三个参数、日期、报告和实际结论一起交接。不要只发一张“通过”的截图。

本机历史回归参考为 49 个用例、38 通过、11 失败，536 行日志；**新电脑、本次任务的结论以自己的实际报告为准**。测试未通过仍可正常生成完整报告，不等于平台执行故障。

## 4. 做实验、回归和验收

- **同工具跨网站**：3 号与 4 号先确认两个同类网站及可比场景；各参数档位保留网站、工具、场景、参数与各次 taskId。只有一个网站时列出缺项，不得生成跨站结论。
- **同网站跨工具**：固定网站、环境与场景，保留两种工具的实际任务、配置耗时、步骤、断言能力和报告体验。当前后端尚未实现 JMeter 执行，不能把本地 JMeter 草稿当成其他工具的真实样本。
- **回归**：5 号在任务详情核对真实失败，记录具体断言和证据；若需要修改场景，由资产负责人在有权限的 Apifox 项目中处理并重新核对版本。当前没有真实 rerun 接口，重新执行时通过新建任务选择登记资产，并手工记录前后两个 taskId。
- **验收**：6 号检查 JSON 往返、非法输入保留、滚轮、窄屏、键盘、后端错误、状态、刷新恢复和报告。记录所用方法和实际截图。

## 5. 归档和已知边界

1. 真实报告使用任务页的后端脱敏产物。令牌、Cookie、Authorization、数据库口令不要放进截图和平台普通日志。
2. 任务页底部「本地演示归档与复测」支持演示 HTML / Markdown / JSON 导出，以及自身归档的模拟复测；它不是后端真实复测。
3. 原始 CLI run.json 不等于可还原整个平台场景的归档。真实三格式导出、报告导入、资源写入等后端接口尚未实现。
4. 未知指标显示“—”。当前后端比率为 0～1；错误率按失败用例数统计，不能保证排除纯断言失败；吞吐量暂为 null，不能据此编造实验结论。
5. 前端源码开发需要另外准备 Node/npm 并安装锁定依赖。普通使用者只运行本包，不需要安装这些开发工具。
