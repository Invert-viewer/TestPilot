# 常见问题与交接排障

## 双击后没有出现页面

先确认已经完整解压，runtime/node.exe 和 dist/index.html 都在包内。用 START.bat 再试一次并阅读窗口提示。脚本不需要管理员权限；没有自动打开浏览器时，手动复制窗口中的本地地址。不要直接双击 dist/index.html，浏览器的 file:// 方式不能替代本地服务。

这是 Windows x64 便携包，本机 Windows x64 已实测。其他系统或架构请由 2 号使用源码和适用的 Node/npm 构建运行。

## 地址不是 5173，或看不到之前保存的演示配置

5173 已占用时会尝试后续端口，以启动窗口为准。浏览器的本地数据按地址和端口隔离；换端口、换浏览器、无痕窗口或清理站点数据都会影响本地演示配置。真实任务由后端保存，连接同一后端后仍可用 taskId 查询。

## 页面能开，但概览、任务或场景读取失败

打开 config.json 核对 backendUrl，重启启动脚本。该值应是 Spring Boot 地址，不是学校官网、被测博客或前端自身地址。跨电脑时 127.0.0.1 不会自动指向部署者电脑。请 1 号确认网络访问与后端监听。

本包的 server.cjs 只代理平台通信，不启动 Spring Boot、MySQL 或 CLI，也不执行请求编辑器中填写的目标 URL。后端不可用会返回明确的 BACKEND_UNAVAILABLE / BACKEND_TIMEOUT 错误，不使用演示任务掩盖。

## 修改 config.json 后启动失败

它必须是标准 JSON：保留双引号，不写注释，不在最后一项加逗号。backendUrl 只填 HTTP(S) 的协议、主机、端口，不附加凭据、路径、查询和片段。不会将令牌填写到这里。可恢复为包内默认 `http://127.0.0.1:8080` 后重试。

## 任务 404，或者报告 409

- 404：核对实际 taskId 与后端是否匹配；其他电脑的空数据库没有原机器的历史任务。
- 409 REPORT_NOT_READY：任务存在但报告尚未就绪，可等待或手动刷新；执行故障/取消时不一定有完整报告。
- FINISHED / FAILED：测试已经完成但有未通过用例，仍应查看完整结果和报告。
- ERROR：查看工具/平台的 errorCode、errorMessage 和已有执行日志，与 1 号定位。

## 本地新增的网站为什么没有改变真实任务目标

网站环境页和资产草稿是浏览器本地配置。真实执行只使用后端登记资产及其来源、环境和受支持的三个参数。请 3 号把真实资产交给 1 号登记，再从真实场景列表选择。

## 为什么另一位使用者收不到我编辑的配置

本地演示配置不是共享云数据库。通过导出 JSON、整段 JSON 录入和原始证据文件交接；本地 ID 改变后重新绑定引用。真实任务则共享实际 taskId，并连接同一个后端。

## 修改源码后，双击打开的页面没有变化

便携脚本使用包根 dist/，不是 source/frontend/src。开发者须构建源码并重新制作交付包，不能只修改 source 目录后期待成品自动更新。源码开发时使用 npm run dev，后端代理在 vite.config.js 配置。

## 如何停止

在启动窗口按 Ctrl+C，或关闭该窗口。只停止这个前端服务；共享的 Spring Boot 和数据库由 1 号管理。
