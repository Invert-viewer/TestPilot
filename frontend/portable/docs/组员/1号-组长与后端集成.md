# 1 号：组长、Spring Boot 后端与集成

## 开始前

你负责真实执行所需的后端、数据库、CLI 与目标站点。这个压缩包只交付前端，后端需要使用原 TestPilot 项目；不要把前端的 server.cjs 当成 Spring Boot 或测试执行器。

## 操作步骤

1. 在后端电脑准备原 Spring Boot 项目、Java 21 和可用数据库，按原项目 README 填写本机配置并启动。数据库口令只保存在该电脑的本地配置或环境变量中。
2. 在同一电脑确认 Apifox CLI 可用且登录有效；准备与已登记场景匹配的目标站点。当前参考场景使用该电脑的 `127.0.0.1:4000`。
3. 用浏览器或接口工具核对 `http://后端地址:8080/api/v1/tool-assets?tool=APIFOX_CLI` 返回 OK、真实场景与版本。
4. 若组员在其他电脑运行前端，给他们提供可访问的局域网后端地址，确认后端监听地址和实际网络访问可用。各人前端仍在自己的电脑本地运行。
5. 解压本包，将 config.json 的 backendUrl 设为你的后端地址，双击启动脚本。
6. 在「任务与报告」新建一次低频任务：循环 1、间隔 100 ms、超时 5000 ms，保存实际 taskId。
7. 用同一 taskId 核对页面、后端接口、数据库记录和原始脱敏报告。FINISHED / FAILED 表示测试未通过；ERROR 和 errorCode/errorMessage 表示工具或平台执行故障。
8. 将可访问后端地址、登记资产 ID/版本、场景/环境、目标站点、实际 taskId 和已知限制交给 2～6 号。不要分发 Apifox 令牌或数据库口令。
9. 任务日志和报告属于后端；组员共享任务时必须连接同一数据库对应的后端。换一套空数据库后，旧 taskId 的 404 是正常的资源不存在。

## 交付给其他组员

- 后端地址与启动条件；登记资产及版本；一次可复现的真实任务。
- 同 taskId 的状态、日志、用例与报告证据。
- 哪些接口尚未实现；对照网站和 JMeter 的接入安排。

报告重点：第 2 章总体架构与后端、第 7 章总结及整合。前端“网站与环境”的本地登记不会自动新增后端资产，也不会改变 CLI 的真实目标。
