# 3 号：网站勘查与 Apifox 测试资产

## 操作步骤

1. 双击启动前端，先确认自己操作的是本地配置还是后端真实场景。
2. 在「网站与环境」记录勘查确认的网站地址、公开可测范围和可比业务标识，不预设不存在的登录、注册或业务接口。
3. 编辑对应环境，核对所属网站、完整 baseUrl 和变量。环境地址与网站同源；保留需要的路径前缀。
4. 在「请求调试」整理请求清单：名称、网站、环境、方法、URL、参数、Header、Cookie 与预期。这里运行的是本地模拟；网站是否真实可访问仍要用实际勘查证据确认。
5. 用逐字段与整段 JSON 往返核对配置。examples 中的 JSON 可用于练习；如果新建后 ID 发生变化，重新选择网站和环境，不能直接沿用别人浏览器的本地 ID。
6. 在有权限的 Apifox 项目中准备真实基础场景和环境，先独立验证可运行；把项目、场景、环境、变量占位名称和运行说明交给 1 号登记后端资产。凭据留在执行环境中。
7. 前端「测试资产」上方出现登记场景后，核对其 ID、版本、scenarioKey 和真实目标。下方新建的本地草稿不会自动完成后端登记。
8. 选择登记场景创建一次任务，记录实际 taskId 和报告。当前参考场景为静态博客 8863397，不代表学校官网勘查已经完成。
9. 与 4 号确认参与对比的同类网站和可比页面；与 5 号交接请求语义及正确的预期结果。

## 交接内容

- 网站/环境/场景/版本对应关系、真实可访问请求清单和勘查日期。
- 必要变量名称、非敏感示例、运行条件、实际 taskId 和原始证据。
- 尚未确认的页面或接口、对照网站缺项和实际遇到的问题。

报告重点为第 3 章被测网站与测试方案；协助第 6 章。公开 HTML 页面请求、JSON 业务接口和浏览器页面行为要分别描述。
