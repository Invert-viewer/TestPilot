# 6 号：页面检查与平台验收

## 操作步骤

1. 完整解压，双击启动脚本，记录实际前端地址、浏览器、日期与分辨率。先按来源标签区分演示数据和真实接口。
2. 遍历八个入口，核对页面名称、来源、空态和可用操作。在桌面和约 390px 窄屏检查导航、表单、图表、日志、宽表和报告。
3. 鼠标停在各页表格内滚动，页面应能纵向移动；窄屏表格应可横向滚动。长弹窗内容可滚动，关闭和保存操作可达；关闭后页面滚动恢复。
4. 新增网站，保持名称为空，切到整段 JSON 再回逐字段，应该允许返回。点击保存才提示必填错误。
5. 修改有效 JSON 后回表单核对同步；输入非法 JSON 后回表单，再回 JSON，原文应保留，最近可编辑配置不被覆盖。任务草稿也按此方法验证。
6. 用 Tab/Enter 操作按钮和输入，窄屏导航可打开/关闭，Escape 返回导航按钮，焦点可见。
7. 取得真实 taskId 后检查状态、增量日志、失败用例的预期与实际、报告查看下载、刷新和深链接恢复。不能用演示日志代替这一项。
8. 分别记录后端未连接、任务 404、报告未就绪、测试未通过与执行故障的反馈。不要为了验收擅自停掉共享后端或破坏 CLI 安装；需要故障环境时与 1 号另行安排。
9. 在「检查验收」新增检查记录，写清步骤、预期、实际、方法、taskId 和证据位置；未执行保持待检查。复测填写来源记录关联，保留旧现象。
10. 对被测网站导航、脚本渲染或点击行为，注明人工/浏览器检查方法；CLI 的 HTTP 断言不能证明这些浏览器行为已通过。

## 交付内容

检查清单、实际截图、任务 ID、浏览器与窗口条件、问题现象、修复前后复验及未验证项目。证据文件需另外发给组长，输入证据路径不会自动上传本机截图。

报告重点为第 5 章页面检查与平台验收，提供至少一个真实问题和复验过程。此前滚轮拦截、空配置切换被阻止的两处问题可作为回归检查项，但你自己的通过结论仍需实测。
