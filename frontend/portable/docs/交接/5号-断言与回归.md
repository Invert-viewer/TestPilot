# 5 号：HTTP 请求断言与回归测试

## 操作步骤

1. 从 3 号取得确认过的请求、场景、变量和正确预期，先区分 HTML 页面与真实 JSON 字段。
2. 在「请求调试」载入或填写请求，按实际内容配置状态码、Header、正文、JSON Pointer 或耗时断言。
3. 切换本地 HTML、JSON、404、超时情形，核对断言如何计算。这里是模拟交互，结果不能冒充真实官网响应。
4. 在「断言回归」补充正常、异常、边界和回归用例，写清预期、实际现象及证据。当前列表保存在自己的浏览器。
5. 连接部署者的后端，创建或打开实际登记场景的真实任务，保存 taskId。
6. 在任务「用例结果」中筛选失败并展开断言。记录预期、实际、失败说明和请求/断言分类，区分响应状态正常但内容错误、传输失败和工具执行故障。
7. 对 FINISHED / FAILED 继续读取完整报告。未知值“—”不等于数值 0；跳过与未评估不能按通过计算。
8. 如需修复场景断言，与 3 号协作在有权限的 Apifox 项目中处理，交 1 号重新核对登记版本；不要认为前端本地用例编辑已经改动了云端场景。
9. 当前后端没有真实 rerun 接口。复验时在“新建任务”中选择实际登记资产，记录旧、新两个 taskId、参数和版本，再对照实际报告。

## 交付内容

提交用例编号、请求/场景/版本、操作步骤、输入、预期、实际、断言结果、两个回归任务 ID 和脱敏报告。历史的 49/38/11 只是参考，本次必须填写实际执行结果。

报告重点为第 5 章 HTTP 请求与断言测试，并向第 6 章提供工具断言和报告体验证据。
